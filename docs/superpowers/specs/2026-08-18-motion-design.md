# 设计：让虫动起来（骨架 · 动作 · 生活史）

> 2026-08-18。上一份设计是 [双语版](2026-08-11-bilingual-design.md)。
> 实施计划见 `docs/superpowers/plans/2026-08-18-motion.md`。

## 为什么是这件事

上线 12 天后的实测（GitHub traffic + 自建 Umami，站点 id 见 `index.html`）：

| | 8/14 | 8/15 | 8/16 | 8/17 | 8/18（至中午） |
| --- | --- | --- | --- | --- | --- |
| 访客 | 117\* | 523 | 234 | **853** | 335 |
| 新增 star | 146 | 84 | 36 | 56 | 14 |

\*当天中午才接通统计。**8/17 是新峰值，高于周刊当天** —— 阮一峰那一波已交棒给
v2ex（144 次引荐）、three.js 论坛、豆瓣、知乎。窗口还开着。

三项数据决定了做什么：

**① 63 种里每人只见到 5~6 种，而且是同样的那几种。** 物种页浏览量几乎完全按左栏
列表顺序衰减：帝王蝶（第 2）1039 → 蜜蜂（第 3）612 → 螳螂 506 → 瓢虫 478 →
蜻蜓 419 → 蚂蚁 313 → 蝉 228 …… 尾巴上石蛾 70、螳蛉 62、蜣螂 61。人均 5.4 页、
停留 91 秒、跳出 25%（这三个数其实健康），但大家是顺着列表点四五只就走。

**含义：第 64 个物种的期望价值接近零。** roadmap 已清空待做清单是对的。下一份
力气必须让每次访问「遇到更深的虫」，而不是「让图鉴里有更多虫」。

**② 十个交互子系统，零个埋点。** Umami 的 event 维度返回空数组。聚焦、剖切、
分层、对比、讲解、小测、搜索、笔记、主题、分享 —— 没有任何一个知道有没有人用。

**③ 唯一那条 issue 是老师要拿去上课**（#3），访问日志里还有人把
`小孙女品鉴一下这个靠谱不` 整句当 URL 打进来。而 README 加粗写着文案未经核校。

所以：**做动画，不做新物种**。而且做「参数化几何能做、扫描 GLB 做不到」的那一类
—— 变形与运动。「完全变态 vs 不完全变态」正是中小学讲昆虫的第一知识点，它顺手
回答了 issue #3，却不需要文案核校（形态阶段是无争议的）。

## 决定架构的一个事实

`leg()` 画的是**线段，不是骨架**：先算出 `kneePt / anklePt / tipPt` 三个绝对坐标，
再在点之间画锥管，全部塞进一个扁平 group。没有关节，所以转不动。D 轮触角摆是靠
`userData.base` 在展台侧重新锚定绕过去的 —— 那招对单段触角行，对三段腿不行。

但同时：

- **62/63 个物种用的是 kit 的 `leg()` / `legPair()`**（只有 `mosquito.ts` 自写）。
  把 `leg()` 内部改成嵌套骨架，是一处改动、62 只虫同时能动。
- `wing()` 已经是 `pivot → blade` 两层，**扑翅的轴现成**。31 个物种在用；
  32 个不用（主要是甲虫，鞘翅与折叠后翅自己写）。

## 架构：三层

### 第 1 层 · kit 长出骨架（rig）

`leg()` 改成嵌套 group：`coxa → femur → tibia → tarsus`，每一节挂在父节点末端，
靠**旋转**摆姿，不再重算端点。

`InsectModel` 加一个可选字段：

```ts
export interface LegRig {
  coxa: THREE.Object3D
  femur: THREE.Object3D
  tibia: THREE.Object3D
  tarsus: THREE.Object3D
  /** 静止姿态的四个关节旋转，动作层以它为基准做偏移 */
  rest: { coxa: THREE.Euler; femur: THREE.Euler; tibia: THREE.Euler; tarsus: THREE.Euler }
  /** 左右侧（+1 = 右，-1 = 左），三角步态要靠它分相位 */
  side: 1 | -1
  /** 前中后（0 / 1 / 2），同上 */
  index: 0 | 1 | 2
}

export interface WingRig {
  pivot: THREE.Object3D
  rest: THREE.Euler
  side: 1 | -1
  /** 前翅 / 后翅 */
  pair: 'fore' | 'hind'
}

export interface InsectRig {
  legs?: LegRig[]
  wings?: WingRig[]
  /** 物种自行登记的可动件：鞘翅、口器、尾须、捕捉足… */
  parts?: Record<string, THREE.Object3D>
}

export interface InsectModel {
  group: THREE.Group
  anchors: Record<string, THREE.Vector3>
  radius: number
  frameRadius?: number
  rig?: InsectRig            // ← 新增，可选
}
```

`rig` 是可选的：没有 rig 的物种照旧静态，现有契约一个字不动。

**这一层的验收线是「渲染结果逐像素不变」。** 默认姿态下新旧两版必须画出同一张图
（用 2026-08-13 那套剪影差集法量，方法见 `docs/model-audit-notes.md`），否则
62 只虫的形态会一起悄悄漂移，而所有形态断言照样是绿的。

### 第 2 层 · 动作驱动（motion）

新建 `src/three/motion/`，纯函数，只写姿态、不碰几何：

```ts
type Motion = (rig: InsectRig, t: number) => void
```

三类：

| 名字 | 覆盖 | 内容 |
| --- | --- | --- |
| `hover` | 悬停类 8 只 | 高频扑翅 + 体轴微浮，蜻蜓/豆娘/蜜蜂/熊蜂/食蚜蝇/草蛉/天蛾/大蚊 |
| `walk` | 62 只通用 | 三角步态 —— 一侧前后足配另一侧中足同步迈（昆虫真实的 alternating tripod） |
| `<species>` | 逐只 | 独角仙掀鞘翅起飞、螳螂捕捉、蝗虫弹跳、水黾划水 |

接进现有的 `frameloop='demand'`：播放时切 `always`，停了切回去。
`prefers-reduced-motion` 一律不动，沿用触角摆已有的门控（`InsectCanvas.tsx`）。

### 第 3 层 · 生活史

`build<Name>()` 之外加可选的 `build<Name>Egg / Larva / Pupa()`，同一个物种文件、
同一套 kit。注册表按导出名发现，沿用 `import.meta.glob` 的既有约定。

**阶段之间不做连续形变。** 毛虫变蝴蝶在生物学上本来就不是连续形变（组织解离 +
成虫盘发育），硬 morph 出来好看但错，与本项目「每处形态都能在代码里追溯到形态学
依据」的立场冲突。改成**离散阶段 + 设计过的转场**：蜕皮与羽化是真实事件，做成
蛹壳裂开 → 成虫挤出 → **翅从皱缩展开**。最后那一段是真连续的，也是最值钱的镜头。

入口是底部现成的那张「生活史 · 完全变态」卡片（`BottomCards`），它现在点了没有
3D 反应。

### 首批 8 只

| 完全变态 6 | 不完全变态 2（对照） |
| --- | --- |
| 柞蚕蛾（蚕宝宝 + 茧）· 帝王蝶（已是第 2 高浏览量）· 独角仙（白蛴螬→黑甲，反差最大）· 西方蜜蜂（巢房幼虫 + 职级）· 中华黄萤（会发光的幼虫）· 神农洁蜣螂（粪球里） | 黑蚱蝉（金蝉脱壳）· 碧伟蜓（水虿） |

蚕、蝉、蜻蜓三只在中文语境里文化共鸣最强；帝王蝶是国际面。

卵 / 幼虫 / 蛹的几何比成虫简单得多（卵是椭球，蛹是带翅芽的光滑荚，幼虫是分节管 +
腹足），估每个 60~120 行而不是成虫的 200~400 行 —— 8 只 × 3 阶段约等于过去一轮
4 只成虫的量。

## 地基（与三层并行，不属于本设计的主线但必须做）

1. **埋点**：Umami 自定义事件。要埋的第一批 —— 物种切换及其来源（列表 / 搜索 /
   图鉴库 / 键盘 / 深链）、工具条六个按钮、标注点点击（哪个部位）、讲解打开与
   完成到第几步、小测作答与得分、笔记写入、主题切换、分享点击，以及
   **左栏滚到第几只** —— 最后这条直接量的就是①里那道天花板。
2. **边缘按语言分流**：Cloudflare Pages Function，`/` 上按 `Accept-Language` 把
   非中文访客送到 `/en/`，带 `Vary: Accept-Language`。现状是非中日韩访客 450+，
   而 `/en/` 只有 42 次落地、4% 浏览量。
3. **首帧性能：先量后改。** 线上实测热缓存 1920 宽下首帧到虫子出现 >5 秒。
   首屏 1543KB 未压缩里 three 占 1030KB、`insects.zh` 只占 156KB（约 10%），
   所以**不预设要拆哪个包** —— 先 profile 出 5 秒花在网络 / 解析 / WebGL 上下文 /
   `<Environment resolution={512}>` 的 PMREM / 2048 阴影贴图 / 模型构建的哪一段，
   再决定动什么。

## 三件必须一起做的（否则重蹈 D 轮覆辙）

1. **全量普查测试写在第 1 层，不是最后补。** D 轮触角摆上线后用户实测抓出 9 只
   自写触角的物种静默哑掉；腿与翅的覆盖面更大。断言每只虫要么有 rig，要么在
   白名单里**显式声明**「本种不动」（如无翅的工蚁、竹节虫的拟态静止）。
2. **目视验收不能省。** 4000 个测试证明不了「它走起来像不像虫」。每只动起来的虫
   在 `/preview.html` 里看四个机位（顶 / 侧 / 前 / 斜），这是 `docs/roadmap.md`
   第 3 条已经吃过大亏的那条规程。
3. **像素不变性门禁。** 第 1 层骨架化后的默认姿态必须与改前逐像素一致。

## 排期

窗口还开着，所以先出能发的东西：

| 阶段 | 内容 | 并行度 |
| --- | --- | --- |
| P0 | 地基三件（埋点 / 语言分流 / 性能先量） | 3 路并行 |
| P1 | rig 契约 + 翅句柄（小） | 单点，不并行 |
| P2 | 悬停振翅 + motion 模块地基 | 单点起，物种可并行 |
| P3 | 腿骨架化（大，风险最高） | 单点，kit 手术 |
| P4 | 三角步态（62 只一起会走） | 单点起，验收可并行 |
| P5 | 生活史 8 只 × 3 阶段 | 8 路并行（照过去物种轮次的作业法） |

P1 之前先出 P2 的振翅，是因为 `wing()` 的 pivot 已经存在，那是最快能发出去的
一件；腿骨架化是主体工程，放在它后面。

## 不做什么

- **不加物种。** 理由见①。
- **不做连续 morph 的变态。** 理由见第 3 层。
- **不把实拍图放进仓库。** 「零资产文件」是这个项目的身份。真要回应 issue #3 的
  实拍图诉求，走运行时从 iNaturalist 拉 CC 图 + 署名的路子，那是另一份设计。
- **不现在抽 kit 成独立库。** 本设计会让 kit 长出骨架层与动作层，现在抽等于把
  API 冻在没有动画的版本上。等 P4 落地之后再议。
