An interactive 3D insect field guide — rotate, zoom, and click the coloured hotspots to explore the anatomy, life cycle, and ecological role of 60 species.

**Live: https://insect-world.pages.dev/en/** · **中文版: https://insect-world.pages.dev**

**Every insect is generated by code at runtime. There is not a single model file in this repository.**

60 species across 14 orders: Coleoptera 28, Lepidoptera 5, Hymenoptera 5, Hemiptera 4, Orthoptera 4, Diptera 3; Odonata, Mantodea, and Neuroptera 2 each; Phasmatodea, Dermaptera, Megaloptera, Blattodea, and Trichoptera 1 each.

Two themes, the same museum by day and by night: **"Specimen Table"** (default — cool grey-green archival board, bronze nameplates, specimen-label inks) and **"Museum at Night"** (gallery black with brass accents, specimens lifted out of the dark by spotlight cones — metallic elytra, membrane iridescence, and the firefly's lantern all read better on a deep ground).

> ⚠️ **About the written content**: the summaries, key figures, life cycles, and trivia for all 60 species **were written by AI and have not been checked line by line against entomological literature or by a specialist**. Treat them as "fun to look at, and a way to learn the shapes" — not as a citable source. Issues are welcome if you spot an error.
>
> The English edition is machine-translated from the Chinese and has not been reviewed by a native speaker or by an entomologist. Scientific names (Linnaean binomials) are identical in both editions and are the only reliable anchor between them.

## Why it is worth a look

Reference field guides ship each organ as a ~3.2 MB GLB asset — bought or scanned. No such asset library exists for insects, so this project took another route: **every species' geometry is generated by TypeScript in the browser**, with no external model files at all.

That is not merely a workaround. Insect morphology is far more regular than viscera: the body divides into head, thorax, and abdomen; the thorax carries three pairs of legs and two pairs of wings; appendages are segmented tapered tubes; wing membranes are supported by radiating veins. Once those structures are parameterised, adding a species means writing a description of its dimensions and colours — not buying another model.

- 14,000–36,000 triangles per species (smallest: earwig at 14,420; largest: Chinese oak silkmoth at 35,732)
- 30–90 ms to build a species in the browser
- ~424 KB gzipped first-load JS (vendor 340 KB, dominated by three.js, plus an 84 KB main bundle)
- Species code is split per-module and fetched only when selected; the desktop post-processing pipeline (103 KB) is a lazy chunk that phones never download
- Surface micro-detail (punctures, striae, pubescence, hexagonal ommatidia) comes from procedural textures generated at runtime

The trade-off is realism: this will not match a 3D scan. What it buys is zero asset dependencies, unlimited extensibility, and morphology that can be traced back to a reason in the code.

## Quick start

```bash
npm install
npm run dev          # main site    http://localhost:5178
                     # model bench  http://localhost:5178/preview.html
npm test             # 4030 tests
npm run build        # tsc --noEmit + vite build
npm run deploy       # build and publish to Cloudflare Pages (run npx wrangler login first)
```

Hosted as a static site on Cloudflare Pages, with no backend. `public/_headers` sets the caching policy: build outputs carry content hashes and are cached immutably for a year, while HTML is revalidated on every request so a new release takes effect immediately.

## How to use it

Pick a species in the left column, or step through with `↑` / `↓`. Drag to rotate, scroll to zoom, click a coloured dot for a note on that body part.

The toolbar on the left: **Focus** moves the camera onto the currently selected part, **Section** cuts along the sagittal plane, **Layers** makes the exoskeleton translucent, and **Compare** floats a comparison strip at the base of the stage.

In the right column, **the guided walkthrough** steps through the anatomy and moves the 3D camera to whichever part is being described; **the quiz** is genuinely answerable — it marks answers, explains them, and keeps score.

## Project layout

```
src/
  three/
    builders/
      kit.ts              modelling toolkit — the foundation for every species
      surface.ts          procedural surface micro-texture (runtime CanvasTexture)
      eyes.ts             hexagonal ommatidia normal map for compound eyes
      venation.ts         parametric wing venation (longitudinal + cross veins)
      <id>.ts             one file per species, exporting build<Name>(): InsectModel
    registry.ts           dynamic per-id species loading (Vite code splitting + LRU VRAM eviction)
    InsectCanvas.tsx      the 3D stage: studio lighting, on-demand rendering, antenna sway
    PostFX.tsx            desktop post-processing (N8AO + Bloom + ACES), lazy chunk
  components/
    TopBar / LibraryPanel / Stage / DetailPanel / BottomCards   the three-column workbench
    Discovery.tsx         guided panel (walkthrough / motion / quiz / habitat)
    CompareBar.tsx        inline comparison strip
    Gallery.tsx           full species overview grouped by order
    InsectGlyph.tsx       60 hand-written SVG silhouettes
  data/
    types.ts              data contract
    insects.zh.ts / insects.en.ts    field-guide data for 60 species
    guides.zh.ts / guides.en.ts      walkthroughs and quizzes
  preview.tsx             model bench (/preview.html)
```

Model-local coordinates: `+X` forward (towards the head), `+Y` up (dorsal), `+Z` to the right; 1 unit = 1 cm of real body length.

`anchors` keys are the single coupling point between the modelling layer and the data layer: every `hotspot.anchor` in the insect data and every `LessonStep.anchor` in the guides must resolve against that species' `anchors`, or the hotspot **disappears silently** — no page error, and both sides' own tests still pass. `three/__tests__/integration.test.ts` exists to pin that seam.

## Adding a species

The registry scans the directory with `import.meta.glob('./builders/*.ts')`, **treats the filename as the id**, and finds the exported `buildXxx()` by its `build` prefix. Dropping a new file in registers it automatically — no existing code needs to change.

The content still has to be written by hand, and the id must match in all four places:

| What | Where | Size |
| --- | --- | --- |
| 3D geometry code | `src/three/builders/<id>.ts` | 200–400 lines, the bulk of the work |
| Field-guide data (scientific name, 6 key figures, 5–6 hotspots, ecology, trivia…) | `src/data/insects.zh.ts` + `insects.en.ts` | one record each |
| Walkthrough and quiz (3–4 steps + 2 questions) | `src/data/guides.zh.ts` + `guides.en.ts` | one record each |
| 24×24 silhouette icon | `src/components/InsectGlyph.tsx` | one small component |

Miss one and the tests will catch it: a data record with no builder file fails the integration test; an `anchor` that does not exist on the model fails the seam test.

## Tests

```bash
npm test     # 4030 tests across 54 files
```

One self-check when writing a morphology assertion: **if I revert the code to the broken version, does this assertion fail?** If not, it is not really an assertion.

There is a harder failure mode the self-check does not cover: **assertions measure numbers, people look at shapes, and the two can be unrelated.** The orchid mantis's petal-like femora asserted "width ≥ 3.5× thickness" and measured 5.75 — green — yet rendered as a few thin plates seen edge-on, making the whole insect look like a pale shrimp, because the quaternion fixing their orientation constrained only the long axis and left roll free. The width-to-thickness *number* was entirely unaffected. Assertions that pin this class of bug have to measure **the quantity the user actually sees**.

The Chinese README documents these lessons in full, including a long list of bugs that only surface at runtime and are caught by neither type-checking nor NaN checks — `<Environment>` suspending an entire subtree, inline callbacks causing infinite reloads, `legPair` not actually mirroring, and the counter-intuitive `spread` semantics in `wing()`.

## Known limitations

- Realism is capped below what a 3D scan achieves. Surface micro-detail is covered by procedural textures, but there are no hand-painted textures and no real fur physics. In exchange: zero asset files and a consistent style across the whole library.
- Observation notes live only in the browser (localStorage) and are lost when you switch devices or clear the cache. "Copy as Markdown" in the avatar menu is currently the only way to take them with you.
- Section and layer views are generic (clipping plane / reduced exoskeleton opacity) rather than per-species anatomical layers.
- Some "related species" lists were written from common names and have not been checked against taxonomic literature one by one.
- The entire English edition is machine-translated, as noted above.
